# WAREHOUSE — общий учёт склада

Статический сайт для RP-проекта. Интерфейс выполнен в тёмной графитовой палитре с бордовыми акцентами по приложенному референсу.

## Возможности

- **Обзор:** общее количество оружия, свободные единицы, выданные единицы и операции за сегодня.
- **Склад:** список свободного оружия, поиск, фильтр по категории, выдача и списание.
- **Закреплено:** актуальный список оружия у игроков и оформление возврата.
- **Журнал:** кто, кому, когда и какое оружие выдал или вернул.
- Добавление оружия с категорией, серийным/инвентарным номером и примечанием.
- Экспорт склада или журнала в CSV.
- Локальный демонстрационный режим и общая база данных Supabase с авторизацией и Realtime-обновлениями.

## Публикация на GitHub Pages

1. Откройте репозиторий **Settings → Pages**.
2. В разделе **Build and deployment** выберите источник **GitHub Actions**.
3. Откройте вкладку **Actions** и дождитесь завершения workflow **Deploy warehouse to GitHub Pages**.
4. После успешного деплоя сайт будет доступен по адресу: https://etozheilyap.github.io/WAREHOUSE/

При каждом следующем push в \`main\` workflow автоматически соберёт сайт и обновит публикацию.

### Как устроен JavaScript-файл

Исходный скрипт хранится в репозитории как сжатый текстовый файл \`app.js.gz.b64\`. Workflow автоматически декодирует и распаковывает его в \`app.js\` при сборке сайта. Для локального запуска можно восстановить его вручную:

\`\`\`bash
base64 --decode app.js.gz.b64 | gzip --decompress > app.js
python -m http.server 8000
\`\`\`

Затем откройте http://localhost:8000.

## Подключение общей базы Supabase

Без Supabase сайт работает в локальном режиме: записи сохраняются в \`localStorage\` текущего браузера. Они **не видны другим людям** и не синхронизируются между устройствами.

Для общего склада:

1. Создайте проект на https://supabase.com/.
2. Откройте **SQL Editor** и выполните целиком файл \`supabase-schema.sql\`.
3. В **Project Settings → API** скопируйте Project URL и публичный \`anon\` / \`publishable\` key. Не используйте \`service_role\` или secret key в браузере.
4. В **Authentication → Users** создайте учётные записи для участников склада. Самостоятельная регистрация на сайте отключена.
5. Откройте опубликованный сайт, нажмите **Настройки**, введите Project URL и публичный ключ, затем сохраните.
6. Войдите под выданной учётной записью.

Настройки базы нужно ввести на каждом устройстве один раз. После входа все участники работают с одними таблицами, а изменения поступлений, выдач и возвратов передаются открытым вкладкам через Supabase Realtime.

## Структура проекта

- \`index.html\` — разметка страниц и диалоговых окон.
- \`styles.css\` — оформление и адаптация под мобильные экраны.
- \`app.js.gz.b64\` — сжатый исходный JavaScript; при публикации workflow восстанавливает \`app.js\`.
- \`supabase-schema.sql\` — таблицы, политики доступа и атомарные функции операций.
- \`.github/workflows/pages.yml\` — сборка и публикация сайта.

## Принцип учёта

Каждая физическая единица оружия — отдельная запись. Выдача меняет статус на \`issued\` и сохраняет игрока; возврат снимает закрепление; списание переводит единицу в \`written_off\`. В общей базе изменение статуса и добавление записи в журнал выполняются одной SQL-функцией.

Поле **«Кто проводит операцию»** заполняется вручную. В первой версии нет ролей администратора/кладовщика: любой вошедший пользователь может добавлять оружие и оформлять операции. Для строгой персональной атрибуции потребуется привязать учётную запись Supabase к профилю сотрудника.
